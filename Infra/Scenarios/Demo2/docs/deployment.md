# Demo2 — Bicep deployment guide

> **Scenario overview:** see [../README.md](../README.md) for architecture, resources, and quick-start deploy.

This guide walks through the **Demo2** Bicep files in detail: modules, parameters, multi-environment deploy, and troubleshooting.

## What gets deployed

| Resource | Bicep file | Purpose |
|----------|------------|---------|
| Key Vault | `modules/keyvault.bicep` | Stores `sql-admin-password` |
| SQL Server | `modules/sql.bicep` | Logical server (public endpoint, TLS 1.2) |
| SQL Database | `modules/sql.bicep` | Serverless GP with Azure free offer |
| Firewall rules | `modules/sql.bicep` | `AllowAzureServices` + optional `AllowClientIp` |

Each environment is a **separate resource group** with its own SQL server, database, and Key Vault.

```
rg-demo2-dev                    rg-demo2-stage
├── Key Vault                   ├── Key Vault
├── SQL Server (sql-demo2-dev-*)├── SQL Server (sql-demo2-stage-*)
│   ├── appdb                   │   ├── appdb
│   ├── AllowAzureServices      │   ├── AllowAzureServices
│   └── AllowClientIp           │   └── AllowClientIp
```

## File layout

```
Infra/Scenarios/Demo2/
├── main.bicep                 # Root template — wires modules together
├── main.dev.bicepparam        # Dev parameters (committed)

├── modules/
│   ├── keyvault.bicep         # Key Vault + secret
│   └── sql.bicep              # SQL server, database, firewall
├── scripts/
│   ├── deploy.ps1             # Deploy script (-Environment dev|stage|...)
```

**Not committed (gitignored):**

- `secrets.local.ps1` — dev password
- `secrets.stage.local.ps1` — stage password
- `main.json` — compiled ARM (generated by `az bicep build`)

## Bicep concepts used in Demo2

### 1. Root template (`main.bicep`)

`main.bicep` is the **orchestrator**. It declares parameters, calls modules, and exposes outputs.

```bicep
targetScope = 'resourceGroup'

@allowed(['dev', 'test', 'stage', 'prod'])
param environment string = 'dev'

var uniqueSuffix = uniqueString(resourceGroup().id, namePrefix, environment)

module sql './modules/sql.bicep' = {
  name: 'sql-deployment'
  params: {
    environment: environment
    uniqueSuffix: uniqueSuffix
    // ...
  }
}
```

Key ideas:

- **`targetScope = 'resourceGroup'`** — deploy into an existing resource group (created by the script).
- **`@allowed`** — restricts `environment` to known values at compile time.
- **`@secure()`** — marks `sqlAdminPassword` as sensitive (hidden in logs/portal).
- **`uniqueString(...)`** — generates a stable hash from inputs so names like `sql-demo2-stage-abc123` are globally unique.
- **`module`** — reuses `modules/sql.bicep` and `modules/keyvault.bicep` as building blocks.

### 2. Parameter files (`.bicepparam`)

Non-secret config lives in **environment-specific** parameter files:

| File | `environment` | Resource group (via script) |
|------|---------------|-----------------------------|
| `main.dev.bicepparam` | `dev` | `rg-demo2-dev` |
| `main.stage.bicepparam` | `stage` | `rg-demo2-stage` |

Example (`main.stage.bicepparam`):

```bicep
using './main.bicep'

param environment = 'stage'
param location = 'australiaeast'
param namePrefix = 'demo2'
param databaseName = 'appdb'
param useFreeLimit = true

param tags = {
  project: 'demo2-sql-free'
  environment: 'stage'
}
```

**Secrets are never in `.bicepparam`.** Passwords are passed at deploy time via `--parameters sqlAdminPassword=...`.

### 3. SQL module (`modules/sql.bicep`)

Naming uses the `environment` parameter:

```bicep
var sqlServerName = take('sql-${namePrefix}-${environment}-${uniqueSuffix}', 63)
```

**Free tier** (Azure SQL free offer) — not the old `Free` DTU SKU:

```bicep
resource sqlDatabase 'Microsoft.Sql/servers/databases@2023-08-01' = {
  sku: {
    name: 'GP_S_Gen5_1'      // General Purpose, serverless
    tier: 'GeneralPurpose'
  }
  properties: {
    useFreeLimit: true
    freeLimitExhaustionBehavior: 'AutoPause'
    maxSizeBytes: 34359738368  // 32 GB
  }
}
```

Requires API version **`2023-08-01`** or later for `useFreeLimit`.

**Conditional firewall rule** — only created when `clientIpAddress` is set:

```bicep
resource firewallAllowClient '...' = if (!empty(clientIpAddress)) {
  name: 'AllowClientIp'
  properties: {
    startIpAddress: clientIpAddress
    endIpAddress: clientIpAddress
  }
}
```

`0.0.0.0` in `AllowAzureServices` is an Azure sentinel meaning “allow other Azure services,” not the whole internet.

### 4. Key Vault module (`modules/keyvault.bicep`)

Creates a vault and stores the SQL password as secret `sql-admin-password`. The deployer’s identity gets access via `deployer().objectId` so the secret can be written during deployment.

## Deploy — dev (default)

### Prerequisites

- [Azure CLI](https://learn.microsoft.com/en-us/cli/azure/install-azure-cli) installed and logged in: `az login`
- PowerShell

### Steps

```powershell
cd Infra/Scenarios/Demo2

# 1. Create secrets file
Copy-Item secrets.local.ps1.example secrets.local.ps1
# Edit secrets.local.ps1 — set $sqlAdminPassword

# 2. Preview changes (optional)
./scripts/deploy.ps1 -WhatIf

# 3. Deploy
./scripts/deploy.ps1
```

This uses:

- Parameters: `main.dev.bicepparam`
- Resource group: `rg-demo2-dev`
- Auto-detects your public IP for the SQL firewall

---

## Deploy — stage (Option B)

Stage is a **separate environment** with its own parameter file and resource group.

### Steps

```powershell
cd Infra/Scenarios/Demo2

# 1. Stage-specific secrets (recommended)
Copy-Item secrets.stage.local.ps1.example secrets.stage.local.ps1
# Edit — use a different password than dev

# 2. Preview
./scripts/deploy.ps1 -Environment stage -WhatIf

# 3. Deploy
./scripts/deploy.ps1 -Environment stage
```

The script resolves:

| Setting | Stage value |
|---------|-------------|
| Parameters file | `main.stage.bicepparam` |
| Resource group | `rg-demo2-stage` |
| Secrets file | `secrets.stage.local.ps1` (falls back to `secrets.local.ps1`) |
| SQL server name | `sql-demo2-stage-<suffix>` |

### Manual deploy (without script)

Useful when learning what the script does under the hood:

```powershell
. .\secrets.stage.local.ps1
$ip = Invoke-RestMethod -Uri 'https://api.ipify.org'

az group create --name rg-demo2-stage --location australiaeast

az deployment group create `
  --resource-group rg-demo2-stage `
  --name "demo2-stage-$(Get-Date -Format 'yyyyMMdd-HHmmss')" `
  --template-file main.bicep `
  --parameters main.stage.bicepparam `
  --parameters sqlAdminPassword="$sqlAdminPassword" `
  --parameters clientIpAddress="$ip"
```

### Validate Bicep locally

```powershell
az bicep build --file main.bicep
```

## After deployment

### Read outputs

```powershell
az deployment group list -g rg-demo2-stage --query "[0].name" -o tsv
# Use deployment name from above:
az deployment group show -g rg-demo2-stage -n <deployment-name> --query properties.outputs -o json
```

### Get password from Key Vault

```powershell
az keyvault secret show `
  --vault-name <keyVaultName-from-output> `
  --name sql-admin-password `
  --query value -o tsv
```

### Test connection from your PC

```powershell
sqlcmd -S <sqlServerFqdn> -d appdb -U sqladmin -P "<password>" -Q "SELECT @@VERSION"
```

If you see a firewall error, redeploy (script auto-detects IP) or add a rule manually:

```powershell
az sql server firewall-rule create `
  --resource-group rg-demo2-stage `
  --server <sqlServerName> `
  --name AllowMyPc `
  --start-ip-address <your-ip> `
  --end-ip-address <your-ip>
```

## Environment comparison

| | Dev | Stage |
|---|-----|-------|
| Command | `./scripts/deploy.ps1` | `./scripts/deploy.ps1 -Environment stage` |
| Bicepparam | `main.dev.bicepparam` | `main.stage.bicepparam` |

| `environment` param | `dev` | `stage` |

Dev and stage are **fully isolated** — different resource groups, different `uniqueSuffix`, different SQL servers.

## Free offer limits

- Up to **10** free-offer databases per Azure subscription
- **100,000** vCore-seconds compute per month per database
- **32 GB** data + **32 GB** backup per database
- When limits are exceeded, database **auto-pauses** (with `freeLimitExhaustionBehavior: AutoPause`)

If stage cannot use the free offer (limit reached), set in `main.stage.bicepparam`:

```bicep
param useFreeLimit = false
```

## Adding another environment (e.g. `prod`)

1. Add `'prod'` to `@allowed` in `main.bicep` (already included).
2. Create `main.prod.bicepparam` with `param environment = 'prod'`.
3. Create `secrets.prod.local.ps1` from the example.
4. Deploy: `./scripts/deploy.ps1 -Environment prod`

No changes to `modules/sql.bicep` are required — the `environment` parameter drives naming and tags.

## Troubleshooting

| Issue | Likely cause | Fix |
|-------|--------------|-----|
| `Parameter file not found` | Missing `main.<env>.bicepparam` | Create the file for that environment |
| `Client with IP ... is not allowed` | Firewall missing your IP | Redeploy or add `AllowClientIp` rule |
| `useFreeLimit` deployment warning | Old API version | Ensure database uses `@2023-08-01` |
| Password with `@` or `!` fails | Shell escaping | Use `secrets.local.ps1` + deploy script (avoids manual quoting) |
| Script parse error | PowerShell syntax | Run from `Infra/Scenarios/Demo2/scripts/deploy.ps1` |
